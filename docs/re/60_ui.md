# 60 — UI object system (controls, control group, GMP layouts)

Scope: the widget toolkit used by title / config / save-load / gallery /
backlog / in-game menu and by the ADV message, name and choice windows.
Natives N_208..N_20f and N_2a7..N_30c. Sprite and layer internals (the
objects returned by `N_2d7`/`N_2d8`, `N_1b*`, `N_c5`…) are documented by the
sprite-core write-up, text rendering by the text write-up, and key/mouse
devices by the input write-up. This file only describes how the UI uses them.

Legend: **[V]** verified in disassembly/decompile, **[G]** inferred/guess.
All addresses are ORE_TUBA.EXE 1.01 VAs. Script arguments are numbered
`p0..pN` in push order (`p0` = first push = `args[0]`).

Tools used: `build/re/fn.sh`, `build/re/x86dis.py`. Two small helpers were
written in the session scratchpad (not in the repo): a SOB "lifter" that
folds the self-modifying operand slots of `build/dis/*.txt` into readable
calls, and a stack-offset tracker that maps factory arguments to vtable-call
arguments. All script excerpts below come from the lifter output.

## 1. Architecture in one picture

```
           scripts (title.sob, config1.sob …)
               │  N_208 GMP loader          N_2a7..N_2b5 factories
               ▼                                   ▼
  DAT_00503268 GmpLoader ──creates──▶ DAT_00503280 ControlFactory (owns every control,
               │                         std::list, "tag" per control, parent layer)
               │ registers (Add)                    │
               ▼                                    ▼
  DAT_005032f0 ControlGroup  ◀── N_2c4 Add / N_2c9 Push / N_2ca Pop
    (hit-test list = tab order, hover, focus, capture, tooltip,
     cursor, event id DAT_005034ac, listener DAT_005034c0)
               │  N_2ba = Update(now) once per script frame
               ▼
   control->OnMouse / OnKey → control->Fire() → group.SetEventId(ctrl.id)
               │
   script:  if (N_2ba() > 0) { id = N_2bb(); value = N_2da(ctrl[id]); … }
```

Key facts:

* The UI is **polled by the script**. Nothing in the engine calls the group
  Update except `N_2ba` [V] (only callers of FUN_00449820 are the vtable and
  N_2ba). If a script does not call `N_2ba` in its frame loop, controls do
  not react at all (hover frames don't change either).
* There is exactly **one** ControlGroup (DAT_005032f0) and one factory
  (DAT_00503280). Modal sub-screens save/restore the group's control list
  with `N_2c9` (push) / `N_2ca` (pop).
* Each control has an **id** (`+0x24`, set by `N_2cb` or the GMP loader).
  Firing a control writes that id into `group+0x1bc` (= DAT_005034ac); the
  script reads and clears it with `N_2bb`. Id −1 means "don't report".
* Ownership: the factory list owns the objects; the group list only
  references them. Destroying (`N_2c3`, `N_2c2`, `N_2bf`) deletes the object,
  whose destructor unregisters it from the group.
* **No engine UI sound effects in this game.** Controls call
  `group->PlaySE(name, idx)` on hover/leave/click with default codes −3/−2/−4;
  the group maps them through slots `+0x1c4/+0x1c8/+0x1cc`, which are
  initialised to −1 and never written anywhere in the EXE [V] (and
  per-control sound info is only settable through `N_2ce`, unused). All
  click sounds heard in game come from the scripts (`N_29c` etc.).

Every factory function (FUN_00453ff0 … FUN_00455040) does: `*out = 0`; `new`
+ ctor; `init = obj->vt[...] (parent = (+0x2c ? +0x18 : +0x14), z, …, tag =
+0x28)`; on failure delete and return the error; otherwise append to the
list, `*out = obj`, return 0. The natives return the object pointer (0 on
failure) — scripts keep it as a handle.

Destruction:
* `N_2c3(&h)` → FUN_004552a0: find in list, delete, unlink; on success `h = 0`.
* `N_2c2(tag, invert)` → FUN_004551e0: delete every control with `tag ==
  ctrl.tag` (invert = 0) or with `tag != ctrl.tag` (invert ≠ 0).
* `N_2bf()` → FUN_00453c90: delete all.
* Engine shutdown also clears group, factory and IME helper (ore_tuba.c:15099).

### 5.3 Update(now) — FUN_00449820 [V]

```
if !active: result=-1; return -1
GetMousePos(mx,my)
moved = (mx,my) != (+0xc,+0x10)
if moved:
    if +0x1c: +0x1c = now                       // restart tooltip timer
    if !capture(+0x14):
        node = first node in list order with ctrl.IsEnabled() && ctrl.IsVisible()
               && ctrl.HitTest(mx,my)
        store mouse
        if node != hover:
            hover?.OnMouseLeave(); if focus && focus != node: focus.OnMouseLeave()
            hover = node; node?.OnMouseEnter(); HideTooltip(); +0x1c = now
    else: node = hover; store mouse
    if node: node.OnMouseMove(mx-ctrl.GetX(), my-ctrl.GetY())
else if hover:                                     // mouse idle → tooltip
    tip = hover.GetTooltip()
    if tip && !shown && tipEnabled && +0x1c:
        t = now - +0x1c
        if t >= delay && (dur==0 || t <= delay+dur): ShowTooltip(tip,mx,my); shown=1
    else if shown && dur && now-+0x1c > delay+dur: HideTooltip()
if hover && hover.OnMouse(lx,ly,mouse): HideTooltip(); return 1
f = focus ? focus.ctrl : null
if vt+0x84(f): return 3                            // text input consumed
if f:
    if f.OnKey(actionMap): return 2
    for a in 0..3: if f.neighbour[a] && action a triggered && SetFocus(neighbour)==0: return 4
if ApplyTab(f, TabDirection()): return 4
return 0
```

`N_2ba` returns this code; it is **not** an event flag. Scripts do
`if (N_2ba() > 0) { id = N_2bb(); if (id >= 0) … }`.

### 5.4 Focus / keyboard navigation [V]

* Focus is a node in the list; `FUN_00448de0(group, node, dir)` sets it:
  `old.OnKillFocus(new)`, then `new.OnSetFocus(old, dir)`. Mouse hover is
  dropped (`FUN_004496a0`).
* Default navigation: Tab / Shift+Tab and the arrow actions move through the
  list order (skipping disabled/hidden), wrapping around.
* If a control has explicit neighbours (`N_2cd(ctrl, left, right, up,
  down)` → `+0x18,+0x1c,+0x10,+0x14`), arrow actions jump to them first.
  Verified with gallery.sob's 3×4 thumbnail grid (left/right are column
  neighbours, up/down row neighbours).
* `OnSetFocus` on Button/CheckButton/HitRegion: because the group policy
  returns 2, the control shows its hover frame and the mouse cursor is
  parked at (799, 599) so it doesn't fight the keyboard highlight. Policy
  1 (warp cursor to control centre, HitRegion uses `+0x38/+0x3c` as the target)
  exists but is not used.
* Action 4 ("decide") on the focused control activates it (§6).
* `N_2c4(ctrl, pos)` inserts at list index `pos` (−1 = append), so `pos`
  defines both the Tab order and the hit priority. ScrollBar inserts
  `[arrow1, bar, arrow2]` at pos, pos+1, pos+2; ListBox inserts its
  embedded scroll bar after itself.

### 5.5 Tooltips [V]

* Configured by `N_2b7(enabled, delayMs, durationMs, font)` (gameinit:
  `N_2b7(cfg(0,11), cfg(0,12), 0, G[902])`); FUN_0041d940 re-applies the
  enable flag and delay from app+0xe4d/+0xe50 when the config changes.
* Text per control: `N_2cc(ctrl, str)` (copied). Title/config/save-load set
  help strings; save-load updates the slot tooltip with the slot description.
* Drawing (FUN_00408a20): measure text with the font, image = text +10 px,
  fill 0xFFFFFFE1 (classic tooltip yellow), 1-px border 0xFF445F97, 4-px
  drop shadow 0x80000000, text at (3,3); the sprite (`+0xf0`) is placed
  below/next to the cursor by FUN_00408970 (clamped to the screen) and
  follows the mouse while shown.

### 5.6 Push / Pop (modal screens) [V]

`N_2c9`: move the current list `{head, tail}` onto the deque, list becomes
empty (focus/hover are reset via `vt+0x68`). `N_2ca`: Clear current list,
restore the saved one. Typical pattern (func_lib L+23270 yes/no dialog,
saveload comment dialog, config entered from the in-game menu):

```
pushed = (N_2c9() == 0)
… create buttons, N_2cb(btn, id), N_2c4(btn, -1) …
loop { yield; if N_2ba()>0 { id = N_2bb(); … } }
N_2b9(); N_2c3(&btn…); if pushed: N_2ca()
```

### 5.7 Cursor shapes (N_2b8 → FUN_00408d50) [V]

`n` 0..6 → (cursor id, tooltip offset): 0,2 → system cursor 0 / 0x14; 1 → own
resource 0x78 / 0x18; 3 → system 5 / 0x16; 4 → system 3 / 9; 5 → own resource
0x79 / 4; 6 → system 7 / 0x16 (ids ≥ 0xd are loaded from the EXE resources as
id+0x6b). Returns 1 if valid. Only `N_2b8(0)` is used by the scripts.

## 6. Control classes

All visual controls own an image object (0x80 bytes, FUN_0043f750) and a
sprite object (0xc0 bytes, FUN_00446570) that is attached to the factory's
parent layer with `AttachToLayer(z, tag, 1)`. Frames are laid out
**horizontally** in the ELG (verified: TL_START.ELG 291×25 = 3×97, CF_ANTI.ELG
456×17 = 4×114, LD_CHK.ELG 918×33 = 6×153, SM_AUTO.ELG 1224×26 = 8×153).
Changing state = setting the sprite's source x to `frameWidth * frame`
(FUN_00446940). Scroll-bar knobs are the exception: their frames are stacked
along the axis perpendicular to the bar.

### 6.1 Button (type 0) [V]

Fields: `+0x30` path copy, `+0x34` frame w, `+0x38` frame h, `+0x3c` u8
rect-hit (else per-pixel alpha test via sprite `vt+0x4c`), `+0x3d` u8
hasDisabledFrame, `+0x3e` u8 hasPressedFrame, `+0x3f` u8 state, `+0x40/+0x44`
colour-key params, `+0x4c` sound-info (0x34 bytes, vtable 0x4ee924; N_2ce),
`+0x50` key-press timer, `+0x54` layer, `+0x58` z, `+0x5c` image, `+0xdc`
borrowed image (N_2a8), `+0xe0` sprite.

Frames = 2 + hasPressed + hasDisabled, order **normal, hover, [pressed],
[disabled]**. SetState (`vt+0x80`, FUN_004c7ed0):

```
frame = state
if state==3 (disabled) and !hasDisabled: frame = 0
elif state>=2 and !hasPressed: frame = state-1     // pressed→hover, disabled→frame 2
```

States: 0 normal, 1 hover/focus, 2 pressed, 3 disabled. Transitions:

| event | from | to / action |
|---|---|---|
| OnMouseMove / OnSetFocus | 0 | 1, PlaySE(hover −3) |
| OnMouseLeave / OnKillFocus | 1,2 | 0, PlaySE(leave −2) |
| OnMouse: left press edge | 1 | 2, return true |
| OnMouse: left released (`!held`) | 2 | 1, **Fire** |
| OnKey: action 4 | 1 | no pressed frame → Fire; else 2 and timer = now+100 ms |
| OnKey while 2 | 2 | when now > timer: 1, Fire |
| SetEnabled(b) | any | b ? 0 : 3 |

Fire (`vt+0x94`, FUN_004d9740): if id ≥ 0 → group.SetEventId(id); PlaySE(click
−4); optional sound-info callbacks. Moving the mouse off a pressed button
returns it to 0 without firing.

Inits:
* from file `vt+0x9c` FUN_004c7ab0(parent, z, path, hasDisabled, hasPressed,
  x, y, blend, alpha, ck, ck2, tag): loads image (FUN_0043f9c0); if `ck2 ≥ 0`
  image `vt+0x24(ck, ck2)`; else if `ck == −1 && blend == 0` → rect hit-test
  on; else `+0x6c = ck`.
* from existing image `vt+0x98` FUN_004c7c70(parent, z, image, hasDisabled,
  hasPressed, x, y, blend, alpha, tag) — the image is shared, not copied.
* `vt+0xa0` FUN_004c7460: procedurally drawn Win32-style bevel button with
  text (unused by this game).

### 6.2 CheckButton (type 1: check box and radio) [V]

Fields: `+0x34/+0x38` frame w/h, `+0x3c` u8 style (0..3), `+0x3d` u8
hasDisabledFrames, `+0x3e` u8 rect-hit, `+0x3f` u8 state, `+0x40` selected
index (radio leader), `+0x44` int* value out-pointer (0 unchecked / 1 checked /
2 disabled), `+0x48` sound info, `+0x4c` u8 "inactive"(no input), `+0x50`
key timer, `+0x54` radio group record (leader only: 0x10 bytes {u8,
vector<CheckButton*>}), `+0x58` leader (members), `+0x5c` layer, `+0xe4`
image, `+0xe8` sprite.

States: 0/1/2 = unchecked normal/hover/pressed, 3/4/5 = checked
normal/hover/pressed, 6/7 = disabled unchecked/checked. `IsChecked =
state ≥ 3 && state != 6` (N_2da).

Frame map (table at 0x4f0f70, `frame = T[style][state]`, frame count =
`T[style][6] + (hasDisabled ? 2 : 0)`; states 6/7 fall back to 0/3 without
disabled frames):

| style | use (GMP type) | states 0..7 → frame | frames |
|---|---|---|---|
| 0 | check box with pressed frames (4) | 0 1 2 3 4 5 6 7 | 6 (+2) |
| 1 | check box, no pressed frame (5) | 0 1 1 2 3 3 4 5 | 4 (+2) |
| 2 | radio with pressed frame (6, 8) | 0 1 2 3 3 3 4 5 | 4 (+2) |
| 3 | radio, no pressed frame (7, 9) | 0 1 1 2 2 2 3 4 | 3 (+2) |

So: check box frames = unchecked n/h/[p], checked n/h/[p], [dis-unchecked,
dis-checked]; radio frames = n, h, [p], checked, [dis, dis-checked]. Bit 0 of
style = "no pressed frame" (keyboard decide acts immediately instead of
showing the pressed frame for 100 ms); bit 1 = radio.

Behaviour: hover `state = (checked?3:0)+1`; leave `(checked?3:0)`; press
`(checked?3:0)+2`; release → Toggle (FUN_004da920):
* check box: `state = (checked ? 0 : 3) + 1` (hover frame of the new value), Fire.
* radio: set checked, leader `vt+0xb4(this)` unchecks the others and stores
  the member index in leader `+0x40`, Fire. Clicking an already checked radio
  re-fires.
* Fire (FUN_004da2f0): SetEventId(id), PlaySE(click).
Radio groups: the first radio created without a leader becomes the leader
(allocates `+0x54`, starts **checked**, `*valuePtr = 1`); later radios pass
the leader and register via `leader->vt+0x9c(this)`. In GMP files a run of
consecutive entries with the same type 6/7/8/9 forms one group (types 6 and
8 alternate to separate neighbouring groups, e.g. CFG1 ON11/OFF12 (6),
ON21/OFF22 (8)).

API: `vt+0x8c(bool)` SetChecked (N_2d9), `vt+0x90(i)` radio SelectIndex(i)
(delegates to the leader; members ≠ i → 0/6, i → 3/7) (N_2de), N_2df reads the
selected index, `vt+0x98(bool)` (N_2dc) [G: set "inactive"].

Inits: from image `vt+0xb8` FUN_004c8500(parent, z, valuePtr, image, style,
hasDisabled, leader, x, y, blend, alpha, tag); from file `vt+0xbc` (same plus
colour-key pair, used by the GMP loader and N_2a9).

## 12. Implementation notes for the C++ port

1. Model one `UIGroup` with an ordered `std::list<Control*>` (+ a stack of
   saved lists) and one `ControlFactory` owning `unique_ptr<Control>`s
   with a tag. Handles given to scripts can be raw pointers or indices;
   scripts only compare them with 0 and pass them back.
2. `Update(now)` must follow §5.3 exactly, including: hit test in list order
   honouring enabled+visible; mouse coordinates passed to controls as local;
   result codes; event id set only by Fire/OnChange; reading it clears it.
3. Inputs needed per frame: mouse position (game coordinates 800×600),
   left button held + pressed-edge, wheel up/down as "buttons" 3/4, action
   map edges for up/down/left/right/decide, Tab and Shift. On touch
   devices a tap = move + press + release in consecutive frames; give the
   pressed frame one frame of visibility.
4. Buttons/checks: frames are horizontal slices of one ELG; the frame index
   rules are in §6.1/§6.2 (keep the 0x4f0f70 table verbatim). Per-pixel hit
   testing (alpha > 0 in the current frame) is the default unless `N_2db(…,1)`
   or the image has no alpha.
5. Keyboard focus parks the OS mouse at (799, 599); on iOS just ignore the
   park but keep "keyboard focus suppresses hover" semantics.
6. Tooltips: optional on touch platforms, but keep the timers so scripts
   that read N_2be/N_2bd behave the same.
7. Unused natives (N_20b, N_2a9, N_2ab, N_2ac, N_2ae, N_2c5, N_2c6, N_2c8,
   N_2ce, N_2d2, N_2d4..N_2d6, N_2dd, N_2df, N_2e1, N_2e2, N_2e4, N_2e5,
   N_2e7, N_2e9, N_2f0, N_2f2..N_2f9, N_303) are never called by the shipped
   scripts and can be stubbed.
