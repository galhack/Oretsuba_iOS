# Lucifen SOB virtual machine (ORE_TUBA.EXE 1.01)

Source of truth: `build/re/ore_tuba.c` (Ghidra decompilation of the whole EXE,
one `// ==== FUN_xxxxxxxx @ addr` block per function), `build/re/natives.c`
(decompilation of every native, `// ==== NATIVE <dec> (0x<hex>) @ addr`),
`build/re/x86dis.py` (capstone helpers: `dis(va)`, `rd(va,n)`, `u32(va)`),
`build/re/fn.sh ADDR...` (print decompiled functions), `build/dis/*.txt`
(SOB disassembly of every script, produced by `tools/sobdis.py`).
Run python with `/Users/a/galhack/ore/.venv/bin/python`.

## Script files (SCRIPT.LPK)
* `SOB0` scene/system scripts, `SOB2` = FUNC_LIB.SOB (library, same layout,
  loaded once, base kept at engine+0xd4), `SOB1` = USER_VAR.SOB (globals).
* SOB0/SOB2 layout: `magic, u32 hsize, [5 reloc tables + u32 0] (hsize bytes),
  u32 code_size, u32 blob_size, blob`. Each reloc table: `u32 n, n×(u32 off, u32 val)`;
  `*(blob+off) = ...`:
  0. `G[val]`: address of user variable `val` (table engine+0x58, 12-byte entries)
  1. `N_val`: native function pointer `val` (table engine+0x38, see below)
  2. `T[val]`: engine-exported variable: T[0]=retTgsExp, T[1]=ScriptBootFlg,
     T[2]=retAppProc (registered by FUN_004228d0)
  3. `L+val`: FUNC_LIB blob base + val
  4. `@val`: this blob base + val (code labels, string/data, self-modifying slots)
* Unrelocated switch-table entries hold compile-time addresses
  `compile_base + off`; compile_base = raw word − target for any table-4 entry.

## Interpreter (FUN_00433630, jump table 0x433b34)
State: `pc` (vm+8), `sp` (vm+0xc, grows upward, `push` writes *sp then sp+=4),
`ret` register (vm+0x10). All operands are 32-bit words that are *addresses*
or immediates; code is self-modifying (instructions store values into operand
slots of following instructions, e.g. `lea 0,@slot` stores the current sp into
the argument slot of the next `native`).

| op | name | operands | semantics |
|---|---|---|---|
|0|end|–|yield: return 1 to caller (resume at next pc next frame)|
|1|ret|–|sp-=4; pc=*sp; if pc==0 stop (return 0)|
|2|retv|a|sp-=4; if *sp==0 stop; ret=a; pc=*sp|
|3|getret|a|*a = ret|
|4|call|a|*sp=pc_after; sp+=4; pc=a|
|5|native|f,args,res|*res = f(args) (args = pointer to arg words)|
|6|jmp|a|pc=a|
|7|switch|i,table…,-1|pc = table[i]|
|8|push|v|*sp=v; sp+=4|
|9|pushm|a|*sp=*a; sp+=4|
|10|pop|a|sp-=4; *a=*sp|
|11/12|spadd/spsub|n|sp±=n|
|13..21|add sub mul div rem mod and or xor|a,b,d|*d = a op b (mod: rem fixed to ≥0 using b)|
|22/23|not/lnot|a,d|*d=~a / !a|
|24/25|sar/shl|a,b,d||
|26/27|incm/decm|a|(*a)±±|
|28/29|incs/decs|n|(*(sp-n))±±|
|30|jz|v,a|if v==0 pc=a|
|31|movi|v,a|*a=v|
|32|movm|a,b|*b=*a|
|33|movmi|v,a|**a=v|
|34|movsi|v,n|*(sp-n)=v|
|35|movsm|n,a|*a=*(sp-n)|
|36|movms|a,n|*(sp-n)=*a|
|37|movss|n,m|*(sp-m)=*(sp-n)|
|38|movsd|n,a|*a=**(sp-n)|
|39|movmd|a,b|*b=**a|
|40|lea|n,a|*a=sp-n|
|41..46|lt le gt ge eq ne|a,b,d|*d=(a ? b) signed|

There is also a JIT (FUN_0049da90/FUN_0049db70) enabled by engine+0x1c; ignore it.

## Natives
Calling convention: `int native(int *args)`; args are consecutive 32-bit
values (pushed in source order, args[0] first); strings are pointers into VM
memory (cp932 / GBK in the Chinese build). Return value is stored to `res`.
Native table = 3 core entries (FUN_004221e0) + 795 entries registered in
order by FUN_004154b0 (`push imm; call FUN_00422710`). So `N_k` = table[k]:
* N_0 0x4221b0 call script by name (DAT_0050382c=2, name→DAT_00503728)
* N_1 0x422190 goto script by name (mode 1)
* N_2 0x4221d0 stop script engine (mode 3)
Only 341 distinct natives are used by the shipped scripts
(`build/re/native_overview.txt` lists them with usage count, callees, globals).

## Script scheduler (FUN_004252d0)
Runs the VM until it yields (`end`) or stops. Mode flag DAT_0050382c set by
N_0/N_1/N_2: 1 = unload current script, load SCRIPT\<name>.SOB, continue at
its start; 2 = push pc, load script as nested (depth DAT_00503724++), when
it returns (ret with null) pop back; 3 = stop.

## Text records
Message strings pushed to N_1ce: `00 <u16 line#> #<name>\<voice>$&<text>$`
(see FUN_00433000 for tag syntax: `<...>` tags, `@nnn`, `[..`, `\` newline,
`$`/`&` terminators). Lead bytes: SJIS 0x81–0x9F/0xE0–0xFC; the Chinese patch
widens them to 0x81–0xFE (GBK).

## Global singletons (subsystems)

Sub-objects assigned near ore_tuba.c:13014 (`DAT_0050324c = app+0x9c0` …)
and :15028 (`DAT_00503258 = param_1 + 0xdc`).
